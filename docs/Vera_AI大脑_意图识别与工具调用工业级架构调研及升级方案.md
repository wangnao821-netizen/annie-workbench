## 二、落地实施三步走路线图 (P1 $\rightarrow$ P2 $\rightarrow$ P3)

### 📌 P1 阶段（快赢·低成本·零风险）：扩展对话口语别名表
- **目标**：解决“查文件说人话识别不了”的问题。
- **动作**：
  1. 复用 `core/checklist/matcher.py` 和 `core/case_folder/` 的现有别名基座；
  2. 扩展构建 `CONVERSATION_SPOKEN_ALIASES` 口语映射字典（例如：*“负债单”、“月结单”、“还款单”、“供楼单”* $\rightarrow$ 归一化到 `existing_loan_statement`；*“粮条”、“出粮记录”、“薪俸单”* $\rightarrow$ 归一化到 `payslip`）；
  3. 让 `lookup_files` 和 `_folder_lookup` 在用户说口语词时直接命中标准材料并触发解析。
- **交付标准**：真实客户文件夹中，输入“查下她的供楼单/负债单/出粮单”，100% 命中对应 PDF 并提取真实摘要。

---

### 📌 P2 阶段（稳扎稳打）：`route_flow` 升级为 LLM 路由 + 规则兜底
- **目标**：解决“关键词撞车导致意图识别僵硬”的问题，承接 WO-26b 规划。
- **动作**：
  1. 升级 `core/flow/route.py` 中的 `route_flow`；
  2. 优先通过轻量 LLM 判定当前语句所属流程（`calc_assess` / `doc_lookup` / `co_create` / `meta_chat`）；
  3. 若 LLM 超时或判断置信度低，自动回退到现有强规则关键词保底。
- **交付标准**：任意闲聊/能力问答/信贷提问不再误触发不相关的卡片或死板模版。

---

### 📌 P3 阶段（重型增量）：基于 `BrainFact` 的结构化槽位落库
- **目标**：彻底消除“多轮对话中重复确认同一事实”的顽疾，实现跨会话持久记忆。
- **动作**：
  1. 规范 `brain_facts` 表的槽位 Schema（`key: spouse_income_type`, `val: PAYG`, `confidence: high`）；
  2. 对话中一旦识别到用户给出的槽位澄清，同步写入 `BrainFact`；
  3. `context_builder.py` 优先读取已落库的 `BrainFact` 事实，从数据源头上切断大模型的重复追问。
- **交付标准**：用户回答过一次“工资/接受”，后续轮次和重新打开会话均 100% 保持锁定状态。
