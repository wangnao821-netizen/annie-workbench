## 一、定位（一句话）

> **Vera 的贷款案件记忆与决策大脑——她说，它记、它答、它建议、她拍板。**

**第一原则：零数据源接入 = 零信任成本。** 客户信息 100% 靠聊天获得，靠内置流程主动询问补齐。文件/邮件/日历等外部数据源一律做成"工具"，按需、经观察验证后才接入，绝不做默认数据源。

**Phase 1 核心价值 = 上下文注入。** Vera 已经在日常高频使用 AI 对话、让 AI 写邮件（中文多轮沟通 → 翻译 → 复制发送）——缺的不是"教她用聊天"，而是 **AI 不知道案件上下文，建议不够贴切**。所以第一阶段不验证"会不会用"，直接做"让 AI 知道上下文"。

## 二、产品形态：对话优先的三层大脑 + 工具包

```
对话层（主入口）：BrainChat（记录/建议/确认/撤销）——Vera 大部分时间在这
    ↓ LLM 路由（自然语言 → 对应流程）
业务 Agent 层（🆕 可累积、可触发、可迭代）：建档 / 跟进 / 申报一致性检查 / 催件 / OS 回复
    ↓ 工具白名单
工具层：BrainTool（原子能力，默认关闭，按需 enable）
    ↓
记忆层（事实底座）：CaseContextEvent（账本）→ BrainFact（结构化索引）→ 蒸馏 → 全景 → AI 上下文
动作层（确认闭环）：AI 出草稿/提案 → Vera 确认 → 执行 → 事件回写（红线：AI 只出草稿）
统计层：analytics（天/周/月）→ 对话给结论 + 仪表盘给全貌
```

**前端**：默认打开对话；全景/统计/待办作为可展开的"记忆仪表盘"（任务卡从主界面撤下，任务引擎留在后台当 AI 的待办模型）。

### 业务流程 Agent 层（大脑的"流程库"，2026-08-12 定稿）

**工具是积木，Agent 是搭好的流程，对话是入口。** 业务流程 Agent 是可累积、可触发的多步流程包：

```
她说一句话（"去这个文件夹做申报一致性检查"）
  → LLM 路由到对应 Agent
  → Agent 按步骤执行（每步调 BrainTool 白名单能力）
  → 产出：结论卡 / 上下文事件 / 草稿
```

**Agent 定义格式（统一为流程包，借鉴 SKILL）**
```
agents/
├── declaration_check.yaml
│   name / description / triggers（自然语言触发词）
│   inputs: { case_id, files: [...] | folder: 路径 }   # 扫描类必须 Vera 指定
│   steps: 1..N（读画像 → 扫指定材料(脱敏) → 提取信号 → 比对 → 结论）
│   tools: 白名单（file_scan/desensitize/llm/event_write/draft_gen）
│   confirm_required: false    # 关键动作（发送/申报）需 Vera 确认
│   acceptance: 验收用例（用真实案例回归）
├── followup.yaml / os_reply.yaml / chase.yaml / ...
```

**生命周期**：触发（对话路由）→ 执行（分步可见、可中断、每步写事件）→ 累积（Vera 说"这个流程固定下来"→ V2 生成器从对话抽取步骤生成 Agent 草稿）→ 迭代（改 yaml + 版本管理）→ 治理（agents/ 目录 + 分类 + 废弃 + 每个 Agent 配验收用例）。

**防线**：分步可见可回滚；Agent 工具白名单；扫描类必须用户指定路径；关键动作确认；Agent 库命名/分类/废弃；Agent 也要验收测试。

**V1**：固化 5 个核心 Agent（建档 / 跟进 / 申报一致性检查 / 催件 / OS 回复）；**V2**：Agent 生成器、Agent 库管理、微信语音触发。

### 能力中心（Agent & 工具管理，2026-08-12 定稿）

**前台用能力（BrainChat），后台管能力（能力中心）——同一配置源。**

- **位置**：设置/更多 → 能力中心（管理面；聊天是使用面）。
- **分区**：
  1. **业务 Agent 列表**：名称 / 描述 / 触发词 / 状态（启用·关闭）/ 最近执行 / 验收状态 → 点开详情可编辑（描述 / 触发词 / 步骤 / 输入参数 / confirm_required）→ 保存为**新版本**（不覆盖旧版）；
  2. **工具 BrainTool 列表**：名称 / 描述 / **启用开关**（工具准入政策）/ 权限说明（如"文件扫描 = 仅 Vera 指定路径"）；
  3. **记忆设置**：双线默认 track、披露标记规则、蒸馏开关、确认策略（高置信自动 / 低置信询问）；
  4. **能力提示区**："你可以让 AI 做什么"（示例触发语，降低使用门槛）。
- **V1 范围**：查看全部能力 + 启用/关闭 + 简单编辑（文本字段）；**V2**：完整 Agent 编辑器 / 生成器 / 一键测试运行。
- **边界**：编辑产生版本记录；Agent 改动需过验收（V2 自动）；能力中心不替代 BrainChat（管理 ≠ 使用）。

## 三、记忆系统架构（L0–L6 + 派生层）

| 层 | 内容 | 载体 | 状态 |
|---|---|---|---|
| L0 会话记忆 | 对话缓冲 | CaseChatMessage | 已有 |
| L1 事实账本 | 确认后事实（不可变事件流，唯一真相源） | CaseContextEvent | 已有，不动 |
| L1.5 结构化事实 | 可查询 KV 事实（收入/银行/金额/决定…） | **BrainFact（新增）** | 🆕 |
| L2 行为/决策日志 | Vera 的决定、纠正、提问、AI 建议（决策级，非活动监控） | **BrainEvent（新增）** | 🆕 |
| L3 语义记忆 | 偏好/经验/历史问答（相似召回） | Mem0 | 保留，降级为可选 |
| L4 蒸馏记忆 | 一句话摘要 + 分层摘要 | context_summary / submission_summary | 已有 |
| L4.5 被动录入层（预留） | Screenpipe 工作摘要 → 候选写入 L1.5/L2 | Screenpipe（工具） | 🛑 **架构保留，数据暂不进入**（V2 评估） |
| L5 程序记忆 | 人格 / 主动询问流程 / 工具包 | System prompt + BrainTool | 设计中 |
| L6 工作记忆 | 进行中事项、待确认问题 | 任务引擎 + 对话待办 | 后台保留 |

### 三条铁律
1. **账本为王**：CaseContextEvent 是唯一真相源；BrainFact/BrainEvent/向量/摘要都是派生索引，可从账本全量重建（幂等脚本）。
2. **确认闸门**：AI 记录分两级——高置信直接记 + 可撤销；低置信反问确认。**对话内容不直接当事实，确认后才入账本。**
3. **双线 + 脱敏不放松**：internal/external 贯穿所有层（BrainFact 必须带 track）；任何向量/嵌入走脱敏，本地 BGE 优先，pii_map 永不出内网。

### 双线模式：三层语义（2026-08-12 定稿）

双线不是"两个桶"，而是三层语义：

```
① 内部真实层（internal）——默认、自动、全量
   对话记录全进这里；只给 Vera 看、只给 AI 咨询用

② 披露边界（disclosed）——internal 事实上的一个开关
   每条 internal 事实可标记"可披露 / 不可披露"（AI 建议 + Vera 确认）

③ 递交呈现层（external）——显式、稀有、确认后
   只在"构建递交画像/银行文档"时产生：AI 起草 → Vera 确认 → 成为 external
```

- **外线可引用集合 = external 事实 ∪（internal 且 disclosed 的事实）**；未 disclosed 的 internal 绝不进外线；
- **零标签负担**：对话记录默认 internal，Vera 不选；只有"生成递交文档/写银行邮件"显式进入 external 模式（入口有明显"递交模式"横幅）；
- **external 是构建品，不是派生品**：系统永不自动把 internal 翻译成 external；
- **复合键 = fact_key + track**：internal/external 平行共存，不互相 supersede；supersede 只发生在同 track 内；
- **track 跟随任务**：BrainChat 分"咨询模式（internal）/ 递交模式（external）"，切换有视觉标识。

### 外线生成的三层防线
| 层 | 作用 | 机制 |
|---|---|---|
| ① 注入硬阻断 | 未 disclosed 的 internal 绝不进入外线生成上下文 | 外线查询只读 disclosed+external；红线测试钉住 |
| ② 草稿披露检查（软提醒） | 草稿生成后 + 手工编辑时扫描是否触及不可披露内部事实 → 黄色警告条提示 | BrainFact undisclosed key 规则匹配先行，AI 语义检查后补 |
| ③ Vera 人工终审 | 复制/发送前自己过一遍（红线保持） | 提醒辅助审阅，不替她决定 |

### 披露检查覆盖两层（业务案例驱动，2026-08-12 增补）

> 真实案例：客户未申报孩子，但银行对账单里出现大量与孩子相关的支出 → 银行追问 → 降低贷款能力 + 前后矛盾 → 只能换银行重新规划递交。

因此披露检查**不只扫草稿文本，还覆盖"将递交的佐证材料"**——但**只按需、不主动扫**：

1. **按需文件披露扫描（不主动扫文件夹）**：只有 Vera **主动指定**时才分析——她贴一个文件地址/路径 → 只扫那一个；她说"看那个文件分析一下" → 只分析那一个。绝不主动扫描整个文件夹或后台遍历。
2. **申报一致性检查**：当她指定"递交这几份文件"时，把 外线申报内容（dependents/收入/负债/职业）vs 这些**被指定文件**可推断内容 → 不一致预警（预防"前后矛盾"）。不指定 = 不检查。
3. **换银行重递审计**：换银行 = 重建外线画像；保留旧外线版本 + 被追问原因，供审计与避坑。

**与工具准入一致**：文件分析是一个 BrainTool，默认关闭；Vera 主动调用（贴路径/点名文件）才运行，结果仅用于该次分析，不建文件索引、不留全量文件数据。

### 申报一致性检查功能卡（2026-08-12 定稿）

作为**流程性功能卡**，由系统在合适阶段**主动提供**、Vera 主动触发执行：

- **触发时机（阶段感知）**：案件进入递交相关阶段（清单将全绿 / 准备递交 / 换银行重递 / 银行追问后重建）且外线画像已有内容 → 主动推卡片；卡片可关闭/忽略。
- **卡片形态**：
```
📋 申报一致性检查
  说明：检查"申报给银行的画像"与"将递交的材料"是否一致，防止银行追问
  状态：待检查 / ⚠️ 发现 N 项不一致 / ✅ 未发现异常
  [开始检查]
```
- **材料选择**：点击后两种方式——多选具体文件，或**贴申报文件夹路径 → 扫该文件夹**（Vera 主动指定，非后台扫描）；内容脱敏后分析，结果不留存、不建索引。
- **结论分层**：✅ 通过（未发现不一致）｜ ⚠️ 预警（逐项列出不一致 + 证据定位 + 建议：申报/换材料/附解释信）｜ 🔴 无法解析（需人工看）。每项可展开证据，可一键生成解释信/补申报提醒草稿（走外线，Vera 确认）。
- **闭环**：检查完成写一条上下文事件（全景可见）；她选择"换材料/申报"后卡片状态更新，避免重复检查。
- **边界**：卡片可忽略；文件夹由她贴路径；结果不留全量材料数据；系统只提醒不替她决定。

**边界**：系统只做矛盾提醒 + 合规边界提示，不替 Vera 决定申报或隐瞒（如实申报是正道，隐瞒有 BID 风险——提醒到，决定权在她）。

### BrainFact 设计要点（待细化施工）
- 字段：fact_id / case_id / key / value / category / track / confirmed_by_event / superseded_by / conflict / valid_from / valid_to
- 写入：事件确认后增量更新；**新旧事实矛盾 → 旧 superseded + 标 conflict，待 Vera 确认**
- 查询：category + key 精确查；sqlite-vec 语义搜兜底
- 外线红线：生成银行文档只查 external 事实，红线测试钉住

## 四、工具包与工具准入政策（重要）

每个外部能力 = 一个 BrainTool：`{ name, description, enabled, paramsSchema, handler }`。**默认全部关闭，按需经观察验证后启用。**

### 工具准入三关
1. **观察关（默认）**：工具先"观察运行"（捕获/输出仅作人工评估，**不写入记忆系统、不作为数据源**），观察 1 周；
2. **可行判定**：捕获质量、覆盖真实工作流、Vera 接受度（是否觉得被监控）、PII 风险实测；
3. **转正**：通过后转数据源（opt-in + 本地隔离 + 明确告知 + 不进云同步）。

### 当前工具状态
| 工具 | 状态 |
|---|---|
| 记忆工具（记录/确认/撤销/全景/统计） | ✅ 大脑内置（Phase 1） |
| Screenpipe（被动录屏/音频） | 🛑 **架构保留（L4.5 层），数据暂不进入记忆系统**；V2 再评估（opt-in + 本地隔离） |
| 邮件进度 / 共享日历 .ics / 文件佐证 / 微信 | ⛔ 未接入，按路线图逐步评估 |

## 五、技术选型（已收敛）

| 项 | 选型 | 理由 |
|---|---|---|
| Agent 编排 | **Pydantic AI** | 与 FastAPI/Pydantic 同族，控制粒度最高（锁版本） |
| 本地向量 | **sqlite-vec + BGE** | SQLite 原生、零新增服务、零出网（验证 Windows wheel） |
| 对话 UI | **Vercel AI SDK** | 流式 + 工具渲染；**只连我们后端 /api/chat，前端无 provider key** |
| 时序图谱 | **不引图数据库** | SQLite superseded_by + category 实现轻量时序事实；规模上来再评估 |
| 语义记忆 | **Mem0 降级为可选** | 脆弱依赖，不作为核心 |
| 生成式 UI | CopilotKit → **V2 候选** | V1 不引入（价值/隐私评估未达预期）；若引入仍只连后端 |

## 六、红线与合规（一步不退）

1. AI 只出草稿/提案，发送/递交/推进必须 Vera 确认；
2. 脱敏闸门不变：出站 desensitize、pii_map 不出内网、双线内外隔离；
3. AI 答不上来说"不知道"，绝不编造；
4. 任何被动捕获（如 Screenpipe 转正后）**数据绝不离开本地、绝不进云同步（WO-06）**；
5. 不监控个人行为：BrainEvent 只记"决策/纠正/提问"，不记"点击/时长"。

## 十、待确认补丁（2026-08-12 增补，标"待确认"）

以下 12 点建议补入/细化，等 Vera 确认后并入正式章节：

### 🔴 影响 V1 成败
1. **对话入口协议**：默认进入"案件对话"（她选/系统建议当前案件）；全局对话不注入单案上下文（除非她点名案件）——上下文注入要落在她实际用的入口。
2. **写邮件工作流（杀手锏）**：中文草稿 → 多轮修改 → 一键翻译英文 → **一键复制**（她仍在 Outlook 发送，系统不代发）；翻译后走外线；**复制后自动生成跟进上下文**（"催件已复制，3 天后问客户回没回"）闭环不断。
3. **确认闸门不打扰**：高置信记录走侧边静默记录 + 对话尾部小字"📌 已记录 2 条 [查看]"；低置信/矛盾才插入一次轻确认（可忽略）。

### 🟡 重要可后置
