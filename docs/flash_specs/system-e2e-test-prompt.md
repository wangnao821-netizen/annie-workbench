## 核心测试方法论体系

本次测试严禁泛泛而谈，必须贯彻以下 5 大成熟工程测试方法论：

1. **用户旅程与角色驱动测试 (Persona & User Journey Testing)**：
   - 深度代入真实用户角色（澳洲贷款 Broker Brandon、助理 Vera、合规审查员），模拟完整信贷业务全生命周期：`存量/新客接案 -> 案卷拓扑识别 -> 资料收集打勾 -> 案情事实提炼 -> 政策合规校验 -> 邮件草稿协同 -> 补件跟进 -> 审批结算 -> 结案归档先例沉淀`。
2. **前后端数据流与状态闭环审计 (Data Flow & State Integrity Tracing)**：
   - 追踪每一个业务动作从 **UI 交互 -> 组件 State -> API 请求 Payload -> 后端 Pydantic Schema -> 领域逻辑/AI Pipeline -> SQLite 数据库持久化 -> 衍生聚合（Context/Facts/Timeline） -> 前端 Store/Mapper -> UI 视图回显** 的全链路，坚决揪出“数据中途丢失”、“字段类型不匹配”、“乱码损坏”、“静默失败”等隐形断点。
3. **跨模块协同连通性审查 (Cross-Module Interoperability)**：
   - 验证上游模块的数据变更与事件触发是否能 100% 驱动下游模块协同（如：案卷关联文件夹后清单是否即刻打勾？识别到卡点后是否自动触发先例推荐？草稿箱确认后是否自动流转并记录时间线？归档后是否自动沉淀知识库？）。
4. **尼尔森十大可用性启发式评估 (Nielsen Usability Heuristics & UX Friction Audit)**：
   - 评估状态可见性（加载骨架屏/空状态/进度反馈）、系统与现实匹配（澳洲信贷术语/LVR/Alt Doc/PAYG）、用户控制与自由（支持撤销、重置、编辑）、一致性与标准、防错与容错提示。
5. **极端边界与韧性测试 (Boundary & Failure Resilience Testing)**：
   - 空文件/超长路径/畸形文件名/特殊字符、非标准目录结构、重名客户、AI 网关超时/降级兜底、数据库并发写冲突。

## 全景测试范围与逐模块排查要求

请依次按以下 8 大核心模块展开地毯式检查，并重点执行交叉协同测试：

### 模块 1：建档双通道工作台（NewCaseSheet）
- **通道一：全新客户建档（BrandNewCaseForm）**
  - [ ] 录入表单所有字段（客户姓名、居留身份 PR/TR/海外、雇佣形式 PAYG/自雇/公司、电话、邮箱、银行、方案类型 Alt/Full Doc、贷款金额、利率、地址、估值）；
  - [ ] AI 极速预填助手（`POST /api/cases/parse-text`）解析效果、字段覆盖率与表单回填连通性；
  - [ ] 物理目录脚手架自动生成（`POST /api/cases/scaffold-folder`）的路径规范、子目录结构与异常防护；
  - [ ] 一客多案（`client_id`）三层匹配算法（同名同邮箱复用 / 同名复用 / 新客生成）的实际运行表现；
  - [ ] 建案后是否自动完成：清单规则预选（15-25项）+ 自动匹配打勾 + 政策检查提示 + 全景事实初始化。
- **通道二：存量客户多房产拓扑导入（FolderTopologyScanner）**
  - [ ] 本地客户根目录（多案卷/重递/转贷轮次）只读扫描与目录名语义解析；
  - [ ] Broker Notes 画像提取（电话/邮箱/收入/身份）到批量导入载荷的传递贯通性；
  - [ ] 批量建档接口（`POST /api/cases/topology-import/batch`）是否同步完成：全量字段持久化 + `folder_path` 绑定 + 即刻触发文件快速关联打勾（`match_checklist_files_for_case`）+ `brain_facts` 初始事实沉淀；
  - [ ] 存量案卷状态映射（`submitted` / `onhold` / `withdrawn` / `active`）与卡点原因识别。

### 模块 2：案件看板与列表（CaseBoard & Kanban）
- **看板流转与交互体验**
  - [ ] 看板 6 大阶段泳道（收集资料 -> 预审准备 -> 已递交银行 -> 审批跟进 -> 补件中 -> 待交割/交割完成）数据统计与卡片渲染；
  - [ ] 卡片关键指标呈现：客户名、机构、金额、LVR、清单进度条、OS 待办数、Boss Pending 标识、Finance 截止倒计时；
  - [ ] 阶段推进（Stage Advance）、暂停（Hold）、恢复（Resume）、撤回、拒绝、重递等状态机流转正确性；
  - [ ] 多维度筛选（银行/阶段/紧急/存量标识）与实时搜索响应体验。

### 模块 3：案件全景概览与证据链（OverviewFacts & CaseFolderCard）
- **客户全景深度展现**
  - [ ] 【身份与关系】：客户姓名、目标、一客多案关联统计徽章（“关联 N 个案件”）、信贷审批官；
  - [ ] 【交易结构】：贷款额、房产估值、LVR 精确计算、银行案号、方案用途、申请利率、当前阶段；
  - [ ] 【关键日期倒计时】：Finance Clause 截止日、剩余天数红黄绿预警徽章；
  - [ ] 【清单进度】：完成项/总项统计、进度条百分比、前 5 项缺失材料动态提示；
  - [ ] 【OS 条件】：银行出具条件清单、待处理计数、红框高亮；
  - [ ] 【风险与瓶颈】：政策引擎检查出的风险提示与瓶颈标注；
  - [ ] 【关联案件文件夹】：路径展示、原生目录选择器、打开资源管理器、一键重新扫描匹配清单。

### 模块 4：事实中枢与上下文大脑（BrainPanel）
- **Brain Facts 事实生命周期**
  - [ ] 事实 9 大标准分类（贷款/房产/收入/职业/身份/负债/披露/特殊/综合）的归类与图标展示；
  - [ ] 事实置信度徽章、来源标记（`broker_notes` / `chat` / `manual`）；
  - [ ] 人工介入：事实锁定（Lock）、解锁（Unlock）、修正（Amend）、新增便签（Manual Note）；
  - [ ] 上下文事件流（Context Events）：双轨（internal 内部 / external 外部）过滤、确认（Confirm）、替代（Supersede）；
  - [ ] 上下文全景预览（Context Preview）与一键导出摘要。

### 模块 5：材料清单与文件 Agent（Checklist & FileAgent）
- **清单自动化与文件操作**
  - [ ] 基于银行政策与案件画像的清单主库规则预选与 AI 补充；
  - [ ] 文件名智能匹配引擎（WO-54）：护照、驾照、流水、工资单、市政费等别名模糊匹配与即刻打勾；
  - [ ] 手动勾选、撤销勾选、新增自定义清单项；
  - [ ] 文件操作（重命名、移动、导入、撤销）与文件事件审计。

### 模块 6：协同草稿箱与沟通中心（DraftsBox）
- **AI 拟稿与确认门禁**
  - [ ] 针对银行补充材料、客户补件追缴、Boss 审批等不同场景的草稿生成；
  - [ ] 人工确认门禁机制（Confirmation Gate）：未确认禁止直接发送；
  - [ ] AI 交互式润色微调（Refine Draft）、微信/邮件格式预览、版本回滚。

### 模块 7：历史档案库与先例智库（Archive & Knowledge Bridge）
- **归档沉淀与智能推荐**
  - [ ] 存量/已结案件批量归档（Batch Ingestion）与留存周期调度（Retention Scheduler）；
  - [ ] 归档时自动提炼实战复盘知识卡并静默同步入库 `KnowledgeEntry`；
  - [ ] 工作台在办案件先例雷达（RecommendedPrecedentsRadar）：根据当前案卷机构与卡点，智能匹配推荐历史破局先例。

### 模块 8：系统设置与基础设施（Settings & System）
- **底层连通与环境韧性**
  - [ ] AI 模型网关配置（DeepSeek / Gemini / 本地模型）与一键连通性测试（`POST /api/settings/ai/test`）；
  - [ ] 桌面端 Electron 无边框窗口控制、托盘最小化、原生文件夹选择器；
  - [ ] 数据文件编码规范性检查（彻底杜绝 Windows GBK/UTF-8 字符集混杂乱码）。
