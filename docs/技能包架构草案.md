# 技能包架构草案（Skill Package）

> 状态：草案（待 Vera 确认后转施工单）
> 日期：2026-08-13
> 来源：Agent架构演进_参考Pi与PrimeAgent.md 的采纳判定；Gemini 对比分析 4 条；用户"业务流程像 SKILL 一样累积"构想
> 关联：docs/Agent架构演进_参考Pi与PrimeAgent.md、docs/flash_specs/wo-26b-pydantic-ai.md、config/agents.yaml（能力中心）

## 一、背景与目标

- 现状：WO-26 已落地"流程包"（YAML 声明式 + 白名单 + 呈现分类 + 规则触发 + 降级），骨架干净但灵活性有限。
- 目标：把"流程包"升级为"技能包（Skill Package）"——Vera 的业务流程可以持续累积、复用、分享，对应"业务流程 AGENT 像 SKILL 一样"的长期构想。
- 四个能力维度（来自 Pi/Prime Agent + Gemini 建议）：
  1. 步骤间数据显式流转（StepContext）；
  2. dialog 共创的版本链 + 一层分叉；
  3. 人闸技能创作（动态生成的安全版）；
  4. 状态卡片契约（CardSchema + payload 版本化）。

## 二、核心模型：技能包 = 流程包的超集

技能包 = YAML manifest + 可选资产（assets）+（白名单内）步骤序列。

### 2.1 manifest 字段（草案）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| key | str | 唯一键 |
| name / description | str | 展示名 / 说明 |
| version | str | 语义化版本 |
| category | enum | agent / tool / flow / knowledge |
| triggers | list[str] | 触发短语（正则） |
| presentation | enum | result_card / dialog / notification |
| permission | enum | read_only / draft / system_config |
| inputs / outputs | dict | 参数与产出契约（见 §3.1） |
| steps | list | 白名单工具步骤（可空：纯模板/知识技能） |
| assets | list | 提示词模板、邮件模板、清单等（非代码） |
| confirm_required | bool | 是否需 Vera 确认（默认 true，出草稿类） |
| status | enum | draft / active / deprecated |
| author | str | 创建人（Vera / AI 提议） |

### 2.2 与现有模块的关系

- 流程包 = 带 steps 的技能（子集）；纯提示词模板技能、知识卡片技能都是合法技能。
- 能力中心（config/agents.yaml + agent_states）→ 技能注册进能力中心，可启用/停用/授权。
- 内置技能放 `config/`（git 真源）；运行时状态放 DB（沿用 agent_states 模式，或新增 skill_versions 表）。

## 三、四大能力维度设计

### 3.1 StepContext 显式契约（数据流转）

- 现状：YAML 已有 `params: { files: "$arg.files" }`、`output: findings` 声明，但 runner 未解析；`chat/loop.py` 中 `args = {}` 写死 → 第一步是**真正接线**。
- 语法（草案）：
  - `$arg.<field>`：用户/路由传入参数
  - `$case_id`：当前案件
  - `$step.<output>`：上一步工具输出
- 运行时：StepContext = 有序 dict；每步按 `inputs` 取参、按 `outputs` 落值。
- Pydantic AI：`RunContext[Deps]` + 强类型 Tool 返回值原生支持；轻量 fallback 用同一契约的有序 dict。
- 纪律：
  - **不做隐式魔法变量池**——每一步用了谁的输出，必须在 YAML 里可见（金融业务可追溯）。
  - 步骤中间结果**不拼进系统提示词前缀**（保护 DeepSeek 前缀缓存）。

### 3.2 会话版本链 + 一层分叉（dialog 共创）

- DB：`CaseChatMessage` 增加 `parent_message_id`（可空）+ `branch_label`（可空）——小迁移。
- 呈现：V1 / V2 / V3 版本链 + 方案 A/B 对比卡；**不做树导航**（Vera 认知负担）。
- 出口：用户确认哪个版本 → DraftCard 进草稿箱（红线：只出草稿）。
- 记忆联动：分支对话共享案件记忆；**只有确认的版本蒸馏进 context summary**；未确认分支只留原文、不污染摘要。
- 压缩：按"主链 + 活跃分支"处理，压缩前摘要写 CaseContextEvent。
- V1 限制：只允许一层分叉（对比场景），不递归。

### 3.3 人闸技能创作（动态生成的安全版）

两条创作路径：
- **路径 A（Vera 手动）**：设置页"技能中心"——填名称/触发语/步骤（白名单选择）/呈现/权限 → 校验通过 → draft。
- **路径 B（AI 提议）**：对话中 AI 发现可复用流程 → 生成技能草稿（YAML + 说明 + 理由）→ Vera 查看/修改/确认 → 激活。**绝不自动激活**。

状态机：draft → active → deprecated（每次编辑出新版本，可回滚——闭环）。

安全边界（红线）：
- 技能**只能调用白名单工具**；不能执行任意代码。
- assets（提示词/邮件模板）是数据，不是代码。
- 需要自定义逻辑的走代码评审流程（如 declaration_check.py 模式），不开放给用户创建。
- 权限分级：read_only / draft / system_config，创建时授予。
- PII 脱敏、只出草稿、PathGuard 等红线对技能同样生效。

### 3.4 状态卡片契约

- 卡片 = CardSchema（表单字段/类型/默认值/校验规则）+ 结果 payload + `payload_version`。
- 交互：前端按 schema 渲染表单 → 提交 → 重跑 flow → 返回新 payload 替换卡片（**不做实时双向绑定；V1 不流式**）。
- 兼容：老卡片按 payload_version 降级渲染，不因契约演进而白屏。
- 单一来源：CardSchema 与流程包 inputs **同源**（由 manifest 生成或引用），避免两处维护。
- SSE 留给后台任务通知，不进卡片实时通道。

## 四、存储与注册

- 内置技能：`config/skills/`（或扩展现 agent_flows 目录）→ git 管理、配置为真源。
- 运行时状态：DB（沿用 agent_states 模式；若需版本历史，新增 `skill_versions` 表：manifest json + status + created_by + reason）。
- 注册表 API（草案）：列表 / 详情 / 创建（draft）/ 更新（新版本）/ 激活 / 停用 / 回滚 / 授权。
- 分类、搜索、状态管理必须有（避免技能库变成新的"空壳"）。

## 五、安全红线与缓存纪律（全技能通用）

1. 只调白名单工具；无任意代码执行。
2. PII 脱敏出站、rehydrate 入站；pii_map 不出内网。
3. 对外只出草稿；PathGuard 校验任何文件操作。
4. 模板用占位符，调用时按**稳定顺序**填充；不注入时间戳/随机内容（DeepSeek 缓存友好）。
5. 技能执行写 AiUsageLog（含缓存命中 token）与上下文事件。

## 八、风险与未决问题

1. 技能库膨胀 → 必须带状态管理 + 分类搜索（已在 §4 约定）。
2. 前端工作量集中在技能中心与状态卡片 → 尽早出提示词，前端并行。
3. CardSchema 版本迁移策略 → payload_version + 降级渲染（V1 简化）。
4. V1 不允许技能间互相调用；V2 再评估（对应"子流程"）。
5. 技能 manifest 是否支持 `schedule` 定时属性 → 与 Phase 2 调度器合并评估。
6. 动态生成技能的质量门 → AI 提议必须附"理由 + 适用范围"，Vera 可拒绝并给反馈（反馈回流为技能改进数据）。
7. Agent 引擎相关 V2 延后项（多 Agent 编排、MCP、Evals、流式、子流程互调、定时后台、确认点前移）见主文档 §十四；技能包 V1 不依赖这些能力。
