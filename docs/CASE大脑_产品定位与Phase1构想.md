## 一、为什么转向"大脑"（背景）

此前系统按"任务工作台"设计：获取任务、获取邮件、日历、文件解析——每加一条管道，就多一层信任成本和摩擦（Vera 要适配系统）。

想通后的结论：**不再碰任何数据源**（文件/邮件/日历）。Phase 1 纯粹打造一个 AI 助手：
- 客户信息 **100% 靠聊天获得**；
- 靠**内置流程主动询问**补齐信息；
- AI 有**稳定人格**（类似 OpenClaw 的拟人助手）；
- 文件/邮件/日历做成**一个一个工具**，按需接入，像一个工具包（Toolbox）。

**零数据源接入 = 零信任成本**。Vera 不需要被读取，只需要被倾听。

## 二、核心架构：大脑是主体，数据源是工具

```
┌────────────────────────────────────────────┐
│  CASE 大脑（唯一主体）                       │
│  · 人格：稳定、专业、贴心的贷款副手           │
│  · 主动询问：内置建档/跟进流程，边问边记       │
│  · 记忆：CaseContextEvent（确认后才落库）     │
│  · 决策：只出建议/草稿，Vera 确认             │
├────────────────────────────────────────────┤
│  工具包（可插拔，按需 enable）                │
│  Phase 1：无外部数据源                       │
│    ✅ 记忆工具（记录/确认/撤销/查全景/统计）   │
│    ⛔ 文件工具 / 邮件工具 / 日历工具 / 任务工具 │
│  Phase 2+：逐个按需接入（像 App Store）       │
└────────────────────────────────────────────┘
```

**一句话**：AI 是操作系统，数据源是 App；Phase 1 只装"聊天 + 主动询问"，App 以后按需装。

## 四、内置流程：主动询问（Phase 1 的灵魂）

AI 不是被动等输入，而是像专业 broker 一样**主动问**。

### 建档流程（新客户）——按专业顺序一步步问，边问边落库
```
客户姓名 → 银行 → 贷款额/房价 → LVR → 用途
→ 收入类型（PAYG/自雇/公司）→ 居住/签证
→ 首付来源（储蓄/赠予/卖房）→ 特殊风险（试用期/ABN不足/负债）
```
- 一次只问 1-2 个问题（不轰炸），答了就记（确认），记了就进入下一个；
- 问完全部 → 生成案件画像 + 政策风险提示（如"自雇 ABN 不足 2 年，ANZ 严格，建议考虑 CBA"）——**这是主动询问的直接回报**。

### 跟进流程（已有案件）
- 每次打开对话，AI 主动问"今天这个客户有什么进展？上次说周三交合同，交了吗？"；
- 缺什么问什么（"你还没说这个客户的收入类型"）——用记忆补全缺口。

### 人格（稳定性格）
- 名字 + 固定语气（专业、直接、不废话、会提醒）；中文；
- 诚实边界：不知道就说"这条我不知道，你说一下我记下来"；绝不编造；
- 记得她说过的话（"上次你说想换 CBA，定了吗？"）——记忆人格。

## 五、工具包架构（Phase 1 就定好接口，为未来预留）

每个工具 = 一个独立能力包：
```typescript
interface BrainTool {
  name: string;              // "calendar_import"
  description: string;       // "从共享日历 .ics 导入事件"
  enabled: boolean;          // 设置里开关，Phase 1 全关
  paramsSchema: {...};       // 参数定义
  handler: (params) => ...;  // 执行（内部走脱敏闸门）
}
```
- 未来接入 = 写一个工具包 + 设置里开开关，**核心大脑零改动**；
- **工具准入三关**：观察关（默认，输出仅评估不写入）→ 可行判定（质量/覆盖/接受度/PII 风险）→ 转正（opt-in + 本地隔离 + 不进云同步）；
- 顺序（按需）：邮件进度工具 → 共享日历 .ics 工具 → 文件佐证工具 → 微信工具；
- CopilotKit：**V1 不引入（价值/隐私评估未达预期），V2 候选**；若未来引入，`useCopilotAction` 正好映射工具包（工具 = 可渲染动作），且 LLM 只连我们后端。

## 六、CopilotKit 集成评估（备选加速器）

- **是什么**：开源 React AI 框架：对话 UI（useChat）、动作渲染（useCopilotAction = Generative UI）、状态暴露（useCopilotReadable）。
- **价值**：动作渲染让 AI 返回的结构化动作渲染成按钮/表单（"建议即按钮"）；对话 UI 加速。
- **红线**：LLM 调用必须走我们后端（脱敏闸门）；CopilotKit 只做前端 UI + 动作注册；**绝不允许直连云 LLM**。
- **澄清**：运行时动态渲染 = 动作模板（安全可控）；运行时让 AI 生成任意代码 = 不安全，不做。
- **风险**：React 19 兼容需 spike 验证；第三方依赖锁定；版本迭代快。
- **时机**：先黑盒验证"大脑模式"，验证成立后再做 1 周 spike，不阻塞主线。

## 七、信任与合规（红线一步不退）

1. **AI 记录两级**：高置信直接记 + 可撤销；低置信反问确认。**对话内容不直接当事实，确认后才落 CaseContextEvent。**
2. **AI 只出草稿/提案**：发送邮件、递交银行、推进阶段必须 Vera 确认（宪法红线不变）。
3. **AI 答不上来说"不知道"**，绝不编造——信任靠诚实建立。
4. **脱敏闸门不变**：出站 desensitize、pii_map 不出内网、内外双线（内部真实/递交呈现）继续有效。

## 八、风险与防线

| 风险 | 防线 |
|---|---|
| 纯聊天建档信息不全 | 主动询问流程 + 每次对话补问缺口 |
| AI 记错 → 记忆污染 | 确认/撤销 + 低置信反问 + 全景可核对删改 |
| 幻觉 | 只基于 CaseContextEvent 回答 + 明说不知道 |
| 人格漂移 | 固定 system persona + 语气模板 |
| 红线 | AI 只出建议/草稿，发送/递交必须 Vera 确认（不变） |

## 十、决策点（等待 Vera 思考成熟后拍板）

1. 纯对话 vs 对话+仪表盘（建议后者：对话给结论，全景/统计给全貌）；
2. AI 记录确认策略（建议：高置信直接记+可撤销，低置信确认）；
3. 任务卡去留（主界面撤下、侧栏保留——任务引擎留在后台当 AI 的待办模型）；
4. CopilotKit 时机（验证后试点，不前置）；
5. 人格设定（名字/语气，由 Vera 定）；
6. 主动询问节奏（一次问几个、什么时候问）。
