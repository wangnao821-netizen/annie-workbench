> 日期：2026-08-12

---

## 一、三条设计原则（比选型更重要）

1. **事实账本是唯一真相源，其余记忆都是"投影"**
   - `CaseContextEvent`（已有）= 事实账本（账本式、可追溯、可撤销）；
   - 语义记忆 / 知识图谱 / 摘要 / 向量检索全部是**从账本派生的索引**——AI 记错了，改账本，索引重建即可。保住信任（可溯、可删改）。
2. **确认闸门**：AI 记录的"待确认"事实不进入正式记忆层；Vera 确认（或高置信+可撤销）后才入账本 → 才能被索引/蒸馏。对话内容永远是"草案"，确认后才变"事实"。
3. **双线 + 脱敏不放松**：内部/递交两轨继续；**任何向量/嵌入也走脱敏**（文本先 desensitize 再送 embedding API，或直接用本地嵌入模型）；pii_map 永不出内网。

## 二、记忆系统分层设计（CASE 大脑）

| 层 | 内容 | 载体（现状/建议） |
|---|---|---|
| L0 会话记忆 | 本次/近期对话上下文（聊天缓冲） | CaseChatMessage（已有，每案件一对话） |
| L1 事实记忆（账本） | 确认后的事实：客户/银行/金额/决定/进展，带 时间+来源+内部/递交 | **CaseContextEvent（已有，保持为唯一真相源）** |
| L2 时序知识图谱 | "谁·何时·说了什么·与什么相关"（客户↔案件↔银行↔任务 关系 + 事实有效期） | 🆕 建议引入（Zep/Graphiti） |
| L3 语义记忆 | 软记忆：客户偏好、团队经验、历史问答（相似召回） | Mem0（规划已定，保留） |
| L4 蒸馏记忆 | 每案件一句话摘要 + 分层摘要（L0/L1/L2） | 已有（context_summary / submission_summary + distill） |
| L5 程序记忆 | 人格 / 主动询问流程 / 工具包定义 | System prompt + BrainTool（见产品构想文档） |
| L6 工作记忆 | 进行中事项、待确认问题、工具状态 | 任务引擎 + 对话待办（后台保留） |

**关键**：L1 账本不变；L2/L3 是**新增的派生层**，负责"记得住、找得回"。

## 三、开源项目推荐（避免重复造轮子）

### 记忆层（核心）

| 项目 | 定位 | 为什么适合 CASE 大脑 |
|---|---|---|
| **Zep（社区版 / Graphiti 时序知识图谱）** ⭐ | 时序知识图谱记忆（who-said-what-when + 实体关系 + 事实时效） | 最贴合"记得她说过的话"：客户↔案件↔银行↔任务实体关系 + 时间有效性；自托管、增量更新 |
| **Mem0** ✅（规划已定） | 语义记忆（用户/全局经验，向量召回） | 客户偏好 + 团队经验库（user_id=case_id / agent_id=global_experience）——保留 |
| **sqlite-vec** | SQLite 原生向量扩展 | 全栈 SQLite，**零新增服务器**；本地向量检索，不必为 embedding 加 Chroma/Qdrant 服务 |

### Agent / 工具调用层（大脑的"手"）

| 项目 | 定位 | 建议 |
|---|---|---|
| **Pydantic AI** ⭐ | 类型化 Agent（工具 schema 自动生成，FastAPI 亲和） | 后端就是 FastAPI + Pydantic——类型天然契合，BrainTool 直接映射 |
| **OpenAI Agents SDK (Python)** | 工具调用 / handoff / guardrails | 备选：gateway 是 OpenAI 兼容，也可用；比 Pydantic AI 更"框架化" |
| **LangGraph** | 状态机/工作流编排 | 若"主动询问流程"要可视化编排再用；Pydantic AI + 代码流程够用则不必 |

### 对话 / UI 层（大脑的"脸"）

| 项目 | 定位 | 建议 |
|---|---|---|
| **Vercel AI SDK** ⭐ | React 聊天/流式/工具调用（主流稳定） | BrainChat 基础对话 UI，推荐 |
| **CopilotKit** | 对话 UI + Generative UI（动作渲染成按钮/表单） | 可选增强：AI 返回动作 → 渲染"确认/草稿"按钮；红线：LLM 必须走我们后端 |

### 嵌入模型（供向量层用）

- 本地：**BGE / bge-m3**（首选，零出网、最省心）；
- 云端：text-embedding-3-small（**必须先 desensitize**，内线内容建议只走本地）。

## 四、推荐的最小组合（避免过度设计）

```
SQLite（L1 事实账本，已有）
  + sqlite-vec（本地向量）
  + Mem0（语义记忆，已定）
  + BrainFact / BrainEvent（新增结构化层，替代 Graphiti 的轻量实现）
  + Pydantic AI（agent 编排）
  + Vercel AI SDK（对话 UI；CopilotKit → V2 候选，V1 不引入）
```

**不建议**：为记忆引入重型服务（Qdrant / Weaviate / Postgres+pgvector）、完整 Agent 运行时（Letta 等）——单用户、SQLite 栈，先用轻量组合。

### 对照分析后的综合采纳结论（2026-08-12）

| 项 | 结论 |
|---|---|
| BrainFact（结构化事实） | ✅ 采纳——CaseContextEvent 的结构化索引/视图，**可从账本全量重建（幂等脚本）** |
| BrainEvent（行为/决策日志） | ✅ 采纳——**决策级**（Vera 的决定/纠正/提问/AI 建议），不是活动监控 |
| 双线 track | ✅ **BrainFact 必须带 track**（internal/external）；外线生成只查 external 事实，红线测试钉住 |
| 事实冲突 | ✅ 新旧矛盾 → 旧 superseded + 标 conflict，待 Vera 确认（确认闸门延伸到事实级） |
| 时序图谱 | ✅ 不引图数据库（Neo4j/FalkorDB），用 superseded_by + category 轻量实现 |
| sqlite-vec + BGE | ✅ 采纳（验证 Windows wheel 在打包环境可用） |
| Agent 引擎 | ✅ Pydantic AI（与 FastAPI 同族，锁版本） |
| 对话 UI | ✅ Vercel AI SDK（只连我们后端 /api/chat，前端无 provider key） |
| Mem0 | ✅ 保留但降级为可选 |
| 检索预算 | ✅ context ≤2000 tokens：BrainFact/语义结果按相关性/时效/任务类型排序，不全塞 |
| 审计 | ✅ BrainFact 变更记录"基于哪个事件、谁确认" |

### Screenpipe 接入政策（2026-08-12 修订）

**架构保留（L4.5 被动录入层），数据暂不进入记忆系统**：
- Screenpipe 作为架构中的被动录入层保留（工作摘要 → 候选写入 L1.5/L2 的设计不变）；
- 但**当前数据不进入记忆系统**（不写入 BrainFact/BrainEvent/蒸馏）；
- 整体评估放 **V2**（捕获质量 / 工作流覆盖 / Vera 接受度 / PII 风险）；
- 未来若转正：opt-in + 本地隔离 + 明确告知 + 数据绝不进云同步（WO-06）；不可行或 Vera 反感 → 弃用；
- 无论何时：捕获数据绝不离开本地。

## 五、需要拍板/评估的点

1. **Zep/Graphiti 是否引入**：最大增量（时序图谱），也是唯一"引入新组件"的决策；先 PoC 一周验证"记得住 + 关系查询 + 时效"是否值回成本。
2. **语义层用 Mem0 还是 Zep 一体**：Mem0 偏"经验/偏好"，Zep 偏"事实图谱"——建议共存（职责不重叠），或先只上 Zep 看够不够。
3. **嵌入走本地（BGE）还是 API（需脱敏）**：建议本地，零出网。
4. **agent 编排用 Pydantic AI 还是 OpenAI Agents SDK**：倾向 Pydantic AI（与 FastAPI/Pydantic 同族）。
5. （已收敛）BrainFact/BrainEvent 采用；Graphiti 不引；CopilotKit → V2；Screenpipe 架构保留、数据暂不进入，V2 评估。
